# Project context examples

A project's `context` holds a business summary of at most 200 words. Both examples below
describe the same invented project.

## Business summary to write

```text
Clay Hours lets the customers of a small pottery studio book a class, pay a deposit and
receive a reminder the day before. It serves the studio's two teachers and 300 regular
customers. Its goal is to replace bookings by phone and email. The scope covers the class
calendar, bookings and reminders; the studio's shop stays out.
```

It says what the project does, for whom, its goal and its essential scope. It stays true
from one session to the next.

## Work log not to write

```text
2026-11-03 session: moved the booking API to the new server, deployed after two retries.
Merged the reminder fix (commit 8f3c2d1). Status: deposits still fail in staging.
Next priorities: 1. fix deposit refunds, 2. finish the calendar export, 3. ask about the
holiday closures.
```

None of it belongs in the context:

- The session report and the deployment detail go in a note or in the chat's transmission.
- The status and the commit go in the tasks they concern.
- The priorities are tasks, each with its own priority.
